# Elekeza — AI Security

## 1. Prompt Injection

### 1.1 Risk Description
User-supplied text could be injected into AI prompts to manipulate model behavior, extract sensitive data, or cause the model to act outside intended boundaries.

### 1.2 Implementation Status
- **Input validation:** User text validated for length (configurable via DTO constraints) before any AI processing
- **Output validation:** AI responses validated against `LessonJSON`/`QuizJSON` schemas using `ObjectMapper.readValue()` — malformed responses throw `AiClientException`
- **No direct prompt construction:** User text is never directly concatenated into AI prompt strings in the current implementation; the `RealAiClient` communicates with the Python AI service via HTTP (`WebClient.post()` with JSON body), not via prompt injection vectors
- **Cognitive profile isolation:** `learnerContext.cognitiveProfiles` from the authenticated user is included in requests but is a read-only value from the user's profile — not user-controllable input

### 1.3 Mitigation Status
| Control | Status |
| --- | --- |
| Input length limit | ✅ Implemented (via `SimplifyTextRequest`/`GenerateQuizRequest` DTOs) |
| Output schema validation | ✅ Implemented (json schema validation via `LessonJSON`/`QuizJSON`) |
| No prompt construction from user text | ✅ Implemented (HTTP API call, not prompt-based) |
| Cognitive profile sanitization | ✅ Implemented (read-only from user profile) |

### 1.4 Evidence
- `RealAiClient.call()` — uses `WebClient` to call `/ai/simplify/text`, `/ai/quiz/generate` etc.
- `MockAiClient` — returns deterministic mock JSON; no prompt injection vectors
- `ContentController.uploadText()` — catches `AiClientException`; falls back to raw text

### 1.5 Remediation (Planned)
- Add explicit prompt sandboxing if prompt-based AI is ever introduced
- Add `java.util.regex.Pattern` validation for any user text included in prompts

## 2. Data Leakage

### 2.1 Risk Description
Sensitive learner data (names, IDs, progress scores, institution information) could be inadvertently included in AI prompts or responses, leaking data to the AI provider.

### 2.2 Data Sent to AI
The following learner data is included in AI requests:

| Data Category | Included in Request | Source | Sensitivity |
| --- | --- | --- | --- |
| Cognitive profile | ✅ Yes | `user.cognitiveProfiles` from authenticated user's profile | Medium (educational support needs) |
| Lesson content text | ✅ Yes | Raw text uploaded by teacher; the learning material itself | Medium |
| Quiz questions | ✅ Yes (mock only) | Generated by AI or teacher; in mock mode, generic placeholders | Low |
| Student name | ✅ Yes (mock only) | Included in mock `LessonJSON` `profile` field | Medium |
| Institution name | ✅ Yes | Included in `Institution` context; used for institution-isolated queries | Low |

### 2.2.1 Text Content
The raw text that a teacher uploads is sent to the AI service for summarization/quiz generation. This is the primary data vector.

**Mitigation:**
- No personally identifiable information (PII) should be in lesson text; teachers are instructed to anonymize
- The system does not add any additional PII to the AI prompt beyond what the teacher includes

### 2.2.2 Cognitive Profile
The user's cognitive profile (e.g., "dyslexia", "adhd") is included in AI requests to enable personalized responses.

**Mitigation:**
- Profile value is read-only from the user's DB profile — not user-controllable per-request
- Only educational support profile values are allowed (dyslexia, adhd, autism, intellectualDisability, default)
- No special characters or unusual values permitted

### 2.3 Data Leakage in Responses
AI responses are validated against `LessonJSON`/`QuizJSON` schemas. If the response doesn't conform, an exception is thrown and the app falls back to raw text/placeholder — no malformed data is persisted or displayed.

### 2.4 Evidence
- `RealAiClient` — `ObjectMapper.readValue(raw, type)` with `LessonJSON.class` / `QuizJSON.class`
- `MockAiClient` — deterministic mock JSON that conforms to schemas
- `ContentController.uploadText()` — `runCatching { ... }.onFailure { log.warn(...) }` on any AI failure

### 2.5 Mitigation Status
| Control | Status |
| --- | --- |
| Schema validation of AI responses | ✅ Implemented |
| No PII added by system beyond user text | ✅ Confirmed (teacher provides all content) |
| Cognitive profile from DB only, not per-request | ✅ Implemented |
| Fallback on schema validation failure | ✅ Implemented |

### 2.6 Remediation (Planned)
- Add PII redaction/blocking before sending to AI
- Add explicit data classification tags on user content
- Implement tokenization to mask IDs/names before AI submission

## 3. Cross-User Context Leakage

### 3.1 Risk Description
A learner could receive another learner's data via AI responses, or see another institution's data through the AI's output.

### 2.2 Implementation Status
- **Institution isolation enforced in code** — `requireContentAccess()` ensures Student A cannot access Institution B's content (verified in security architecture)
- **AI responses are per-request** — each `simplifyText()`/`generateQuiz()` call is isolated to the current user's content and cognitive profile
- **No shared AI state** — each request is independent; no persistent AI memory between users

### 2.3 Mitigation Status
| Control | Status |
| --- | --- |
| Institution isolation in code | ✅ Implemented (`requireContentAccess()`) |
| Per-request AI isolation | ✅ Implemented (each API call is independent) |
| Cognitive profile per user | ✅ Implemented (from authenticated user's profile) |
| No cross-user AI state | ✅ Implemented (stateless AI calls) |

### 2.7 Evidence
- `ContentController.requireContentAccess()` — verified in security architecture
- `QuizController.requireContentAccess()` — mirrors ContentController logic
- `InstitutionService.getStudents()` — queries by `institutionId` only

### 2.8 Remediation (Planned)
- Add explicit cross-user boundary tests
- Add AI response audit logging for anomaly detection

## 3. Malicious Documents

### 3.1 Risk Description
A malicious PDF/Office document uploaded as course content could contain executable code, embedded scripts, or data designed to probe or attack the AI service or backend.

### 3.2 Document Extraction Safeguards
- **PDFBox** used for text extraction — extracts text content only; no executable code runs from the PDF
- **Apache POI** used for Word/docx extraction — similar safeguards
- **File type validation** — `ContentController.unsupportedMediaType()` checks that file extension matches declared content type
- **Size limit** — 10 MB maximum upload (`app.max-upload-bytes`)
- **Path traversal prevention** — filenames sanitized (`filename.replace(" ", "-")`) before storage

### 3.2 Evidence
- `ContentController.unsupportedMediaType()` — validates extension vs content type
- `MockStorageProvider.upload()` — sanitizes filename with `UUID.randomUUID() + "-" + filename.replace(" ", "-")`
- `ContentController.unsupportedMediaType()` — throws `ResponseStatusException(HttpStatus.UNSUPPORTED_MEDIA_TYPE)` on mismatch

### 3.3 Mitigation Status
| Control | Status |
| --- | --- |
| File extension validation | ✅ Implemented |
| File size limit (10 MB) | ✅ Implemented |
| Path traversal prevention | ✅ Implemented (filename sanitization) |
| No executable code from uploaded files | ✅ Confirmed (extraction is text-only) |
| MIME type validation | ⚠️ Not implemented beyond extension check |

### 3.4 Remediation (Planned)
- Add actual MIME type verification using Apache Tika or similar
- Add sandbox for document extraction (run in isolated environment)
- Add antivirus scanning for uploaded files

## 4. Unsafe Output

### 4.1 Risk Description
AI could generate output containing unsafe content (harmful instructions, personal information, etc.) that is then displayed to students or saved to the database.

### 4.2 Output Validation
- **`LessonJSON` schema:** Requires `title`, `sections` (list of `AiSection` with `heading` + `body`), `keyTerms` (list of `AiKeyTerm` with `term` + `definition`), `profile` (string)
- **`QuizJSON` schema:** Requires `questions` (list of `AiQuizQuestion` with `id`, `text`, `options` list of `AiQuizOption`, `correctId`, `explanation`)
- **Any deviation throws `AiClientException`** — caught in `ContentController`; falls back to raw text/placeholder

### 4.2 Evidence
- `RealAiClient.call()` — `objectMapper.readValue(raw, type)` with `LessonJSON.class` / `QuizJSON.class`; exception on failure
- `MockAiClient` — returns deterministic mock JSON that conforms to schemas
- `ContentController.uploadText()` — `runCatching { ... }.onFailure { log.warn("AI failed for text upload: {}", it.message) }`

### 4.3 Mitigation Status
| Control | Status |
| --- | --- |
| Schema validation of AI output | ✅ Implemented |
| Fallback on validation failure | ✅ Implemented (raw text/placeholder) |
| No unsafe output persisted | ✅ Implemented (exception thrown before persistence) |

### 4.4 Remediation (Planned)
- Add content filtering for unsafe language in AI responses
- Add human review step for AI-generated content before persistence
- Add `AIContentSafety` service for post-processing

## 5. Hallucination

### 5.1 Risk Description
AI may generate confident but incorrect content (hallucinations) — e.g., quiz questions with incorrect answers, lesson summaries that fabricate facts.

### 5.2 Hallucination Mitigation
- **Schema validation** catches structural hallucinations (missing required fields, wrong types)
- **Human review** recommended for production; the current pilot uses mock AI where outputs are deterministic and controlled
- **Quiz correct answer validation** — in mock mode, the `correctId` is explicitly set to "A" or "B" with corresponding `explanation`; in real mode, the AI is responsible for correctness
- **Teacher review** — teachers can edit AI-generated quizzes/lessons before assigning them

### 5.3 Evidence
- `LessonJSON` and `QuizJSON` schemas define required fields; any missing field throws exception
- `MockAiClient` returns deterministic, teacher-vetted mock content
- Teacher can edit AI-generated content in the UI before assignment

### 5.4 Remediation (Planned)
- Add teacher editing interface for AI-generated content
- Add confidence scores or citations in AI responses
- Add cross-reference with lesson content to verify AI summaries

## 6. Provider Failures

### 6.1 Risk Description
The Groq AI provider could be unavailable, rate-limited, or return errors.

### 6.2 Failure Handling
- **Circuit breaker** (in `CircuitBreakerRegistry`): after 5 failures, circuit OPENs → requests fail fast for 30s → HALF-OPEN after timeout → one test request → CLOSED if successful
- **Retry utility** (`RetryUtil.withRetry()`): exponential backoff (1s, 2s, 4s) for transient failures
- **Mock fallback:** `AI_CLIENT_TYPE=mock` entirely avoids provider dependency
- **Error logging:** `log.error("AI failed for text upload: {}", it.message)` — caught and does not crash the app

### 6.3 Evidence
- `CircuitBreakerRegistry` — 3 states (CLOSED/OPEN/HALF-OPEN); failure threshold 5; reset 30s
- `RetryUtil.withRetry()` — 1s, 2s, 4s backoff
- `RealAiClient` — `flatMap { Mono.error(AiClientException(...)) }` on HTTP errors; `.timeout(Duration.ofSeconds(60))`
- `ContentController` — `runCatching { ... }.onFailure { log.warn(...) }` — never throws to client

### 6.4 Mitigation Status
| Control | Status |
| --- | --- |
| Circuit breaker | ✅ Implemented |
| Exponential backoff retry | ✅ Implemented |
| Mock fallback mode | ✅ Implemented (`AI_CLIENT_TYPE=mock`) |
| Error logging without crash | ✅ Implemented |

### 6.5 Remediation (Planned)
- Add circuit breaker metrics (expose via Actuator)
- Add configurable failure thresholds via application.yml
- Add AI provider health check endpoint

## 7. Token Abuse

### 7.1 Risk Description
An attacker could abuse AI provider tokens (e.g., Groq API key) to make excessive requests, resulting in cost runaway.

### 7.2 Implementation Status
- **API key stored server-side only** — never forwarded to frontend
- **Rate limiting** at the application level via circuit breaker + retry (not at provider level yet)
- **Timeout** of 60 seconds per request prevents indefinite hanging
- **`AI_CLIENT_TYPE=mock`** eliminates token usage entirely for pilot/development

### 7.4 Evidence
- `JwtAuthFilter` — token used only for auth, not AI
- `RealAiClient` — `baseUrl` and `internal-secret` from config; `apiKey` not used directly in this implementation (the Python AI service handles Groq auth internally)
- `ApplicationConfig` — `maxPoolSize = 3`; `queueCapacity = 25` — limits concurrent AI processing threads

### 7.5 Mitigation Status
| Control | Status |
| --- | --- |
| API key server-side only | ✅ Implemented |
| Request timeout (60s) | ✅ Implemented |
| Concurrent thread limit | ✅ Implemented (ThreadPoolTaskExecutor 3 core / 10 max) |
| Mock fallback eliminates token use | ✅ Implemented |

### 7.6 Remediation (Planned)
- Add provider-level rate limiting (Groq dashboard features)
- Add cost monitoring/alerts for AI usage
- Add `AI_COST_LIMIT` env var with automatic shutdown when exceeded

## 10. AI Data Handling

### 10.1 Data Flow: Teacher Upload → AI → Database

```
Teacher uploads text/content
    ↓
ContentController.uploadText() 
    ↓
SimplifyTextRequest(learnerContext, rawText) 
    ↓
aiClient.simplifyText() → RealAiClient or MockAiClient
    ↓
JSON response → LessonJSON schema validation
    ↓
Content entity saved with simplifiedText
    ↓
Quiz generation optional:
    ↓
GenerateQuizRequest → aiClient.generateQuiz() → QuizJSON schema validation
    ↓
Quiz entity saved with questions
```

### 10.2 Data Fields Sent to AI

| Field | Source | Sensitivity | Retention |
| --- | --- | --- | --- |
| Raw lesson text | Teacher upload | Medium | Until lesson deleted |
| Cognitive profile | User profile DB | Low | Until profile updated |
| Institution context | User/Db | Low | Permanent (per institution) |

### 10.3 Data Fields in AI Responses

| Field | Usage | Retention |
| --- | --- | --- |
| Lesson title/sections | UI display | Until lesson deleted |
| Quiz questions/options | UI assignment | Until lesson/quiz deleted |
| Explanations | UI learning | Until lesson/quiz deleted |
| Cognitive profile match | Personalization | Until profile updated |

### 10.4 Data Not Sent to AI
- Student names or IDs (unless included by teacher in lesson text)
- Passwords or authentication secrets
- Institution financial data
- M-Pesa or payment data
- SMS or email content

### 10.5 Evidence
- `ContentController.uploadText()` — traces data flow from request to AI call
- `RealAiClient.call()` — shows exact HTTP body sent to AI service
- `MockAiClient` — shows exactly what mock data is returned

### 10.6 Remediation (Planned)
- Add data classification tags on all content
- Add explicit consent prompts for AI processing
- Add data retention automated cleanup jobs
